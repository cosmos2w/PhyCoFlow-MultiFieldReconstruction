# Experiment artifacts and storage

Keep reusable code, reviewed protocols and selected reading material in the HOME checkout. On this host, create generated campaign payloads under `/data2/wanglz/PhyCoFlow-MultiFieldReconstruction/` and expose a stable case-owned path under `cases/<case>/runs/`. That path may resolve through an alias at `runs/` or at the campaign itself; do not assume every campaign directory is a separate symlink. Before launch, verify the DATA2 mount, write access and capacity, and establish and verify the case-owned path. Never silently fall back to HOME or change an existing alias target. See [the storage map](Storage_Map.md) for the current locations and legacy exceptions.

`datasets/` is a local catalog and contract: existing dataset links may point to other approved storage or legacy owners. Create new project-owned datasets on DATA2 and expose local catalog links. Do not move or duplicate existing datasets merely to organize a campaign; handle an explicitly authorized migration separately. See [the dataset catalog](../datasets/README.md).

## Plans, reports and archives

Use `UpdatePlans/` as the research reading entrance. Place approved plan reading copies under `UpdatePlans/_Plans/<campaign>/` and approved publication reports under `UpdatePlans/_Reports/<campaign>/`; distinguish current material from historical copies in their indexes. Use `_bk/` for closed plan and report reading copies and for appropriately archived inactive run collections. Preserve original frozen documents, source identities and historical paths: a reading copy may adjust navigation and label dated status, but it is not the scientific source. Do not rename a path-bound attempt or move active work to make the layout uniform; mark its archive status in the campaign index instead. Retain ignored compatibility aliases while frozen references need them. Known broken historical links are inventoried legacy state, not evidence that every legacy document has been repaired; new portable publications must pass their own checks.

An approved report publication is a physical, portable bundle: Markdown, every included PNG preview, its figure PDF master, and the main PDF. Keep the immutable original report and raw assessments in the campaign. The publication evidence index identifies the original report, relevant evidence paths and hashes, and any presentation-only changes. Local-only raw artifact paths should be described as such rather than presented as GitHub-accessible files. If the original lacks a main PDF, identify a newly rendered publication PDF rather than implying an original existed.

For Markdown, embed PNGs with relative paths and link PDF masters separately. Retain all included panels, meaningful captions and a figure index. A reconstruction figure displays fieldwise relative L2 or RMSE on its error panel, or on the reconstruction panel when there is no error panel, using the plotted prediction and reference on the declared physical mask and units; if no reference exists, label the error unavailable. Validate local links and heading fragments after URL normalization with `python tools/docs/check_markdown_links.py UpdatePlans/_Reports/Coherence_Adaptive_Repair --portable`, substituting the relevant publication bundle; install the project's `docs` extra if needed. Scope local checks to the portable bundle, since the wider `_Reports/` tree also contains intentionally local legacy material. This rejects local dependencies on symlinks or paths outside the selected checkout root; external web URLs are not checked. Also decode the PNGs, inspect the rendered report and every PDF page, and check PDF link annotations. Repeat the checks after relocation or regeneration and on a clean export containing the files selected for Git. A filesystem path that resolves through a symlink does not prove that a viewer will resolve a relative `..` link the same way.

Track only approved source, plans, compact evidence indexes and intentionally published report bundles. Datasets, checkpoints, prediction banks, caches, routine generated outputs and machine-specific aliases remain local and ignored; this applies to both file and directory symlinks. Git records a symlink's text rather than its DATA2 contents. Check the actual alias entry with `git check-ignore -v` and inspect the staged paths; a directory-only pattern may not ignore a symlink to that directory. An ignore rule does not untrack an already tracked file, so review the selected Git diff and existing tracked exceptions instead of assuming an ignored parent is absent from Git. Do not broadly add a research tree just to publish one report.

## Campaign organization

Each campaign has one `README.md` index at its logical root, linking to its plan, frozen configuration and source identities, attempts, evidence, reports and applicable restrictions. Group new campaign contents by purpose; create the groups as needed:

```text
<campaign>/
  README.md       navigation and campaign identity
  configs/        resolved configurations and manifests
  operations/     launch, completion, resource and cost receipts
  sources/        immutable SOURCE snapshots and identities
  runs/           formal/, qualification/ and pilot/ groups, named arms and immutable attempt IDs
  artifacts/      fitted banks and reusable generated artifacts
  assessment/     split-gated panels, metrics and evidence
  reports/        original reports and figure masters/previews
  _bk/            new closed-material archive where safe; retain legacy archive/ paths
  cache/          explicitly disposable, reproducible caches
```

Keep reusable tools in tracked source; frozen execution copies and their provenance remain campaign artifacts. Use descriptive method names for new experiments, runs and comparison configurations consistently in plans, configs, logs, figures, reports and output paths; do not introduce single-letter experiment aliases. Use unique attempt directories and preserve failed, paused and completed attempts, their checkpoints and logs; never overwrite a previous attempt or present a restart as the original execution. Keep complete training histories and PDF/PNG loss curves in the run's `logs/`: first when history is available, every 10 completed epochs, and at validation, pauses and completion. Preserve mathematical symbols, literal historical IDs and hash-bound paths. Record physical and logical locations, source/config/code hashes, split and population, seeds/coupling and artifact provenance. Capture complete job wall-time and GPU lease boundaries, distinguish independent CPU work from CPU time inside its own GPU lease, and retain failed-attempt costs. Forecasts and incomplete timers are not measured zeros.

Keep recording proportionate to the model question. A complete enclosing job timer can cover routine helpers; retain useful child breakdowns without charging them again or qualifying every bookkeeping command. Forecast GPU inference and CPU metric-scoring work separately, including the result-delivery tail. Reuse saved predictions and immutable reference features; deployment benchmarking is opt-in under the project instructions in `AGENTS.md`. Preserve missing clocks explicitly and use justified bounds only where they affect a claimed cost comparison. Administrative completeness must not block independent experiments or valid field/coherence results. These defaults do not amend an active campaign's frozen protocol or authorize changes to running jobs.

## Verified migration

Relocate existing material only when it is terminal and the task authorizes migration. Verify ownership, open handles, active dependencies, aliases, target mount and capacity before copying. Never move, replace or relink an active run. Preserve originals until the copy and references have been independently verified; remove a verified duplicate only when cleanup is authorized in the task scope. Keep uncertain or unique material and consolidate proposed deletions into the final review list.

Copy to a distinct target, preserving content, required metadata, symlink text and in-scope hardlink groups. Use `tools/storage/verify_campaign_relocation.py` for read-only `inventory`, `compare` and post-alias `links` checks, with sealed receipts outside inventoried trees. Compare hashes, mode, ownership, modification times, symlink text and hardlink relationships; directory size, allocation and physical inode numbers may differ across filesystems. Verify any authorized link rebases and every affected logical and viewer-resolved reference. Re-inventory after renaming a staging directory so the final target is the one verified. The helper does not establish quiescence, perform the move, or check ACLs and extended attributes; inspect those separately when relevant.

An inode can have hardlinks outside the migrated tree. Preserve in-tree relationships, record external hardlink counts and disclose any boundary separation when copying across filesystems; the external originals remain untouched and may diverge if later written. The inventory comparison reports that difference, so reconcile it explicitly rather than claiming an exact match. If another path depends on shared inode identity, retain the original until that contract can be preserved. Record every other approved difference, including a necessary symlink rebase, and investigate all unexplained differences before creating or changing an alias. A compatibility alias may preserve access while still changing an immutable resolved-path string; check both contracts.
