# Test_1002 checkpoint retention review

Reviewed October 6, 2026. This supersedes the first cleanup pass’s broad recommendation to keep every scientific checkpoint. A checkpoint being produced by a scientific run does not make every snapshot useful. Retention should preserve distinct measured comparisons and essential provenance, rather than every early selection, recovery alias, profile and review copy. This is an audited recommendation: no checkpoint has been deleted in this review.

## Recommendation

Keep **32 model files (2.61 GiB)** from the **384 files (29.13 GiB)** currently stored. The exact candidate removal list contains **352 files (26.52 GiB)**. This estimate covers full model/review checkpoints and the retained inference export, not every `.pt` tensor artifact, numerical array, log or receipt. The original trained SOURCE outside `Test_1002` remains protected and is not included in these counts.

The core of the recommendation is nine scientific snapshots plus one optional, small inference export: R5 N100, F100/F150, S100/S150/S200, independent SOURCE seed43_100, R4 Simple100 and R4 Adaptive200. These ten files occupy about 0.77 GiB. The additional 22 files preserve compact R1–R4 controls, component/optimizer comparisons, independent confirmations, the R2 locked mature130 selection, and an actual R4 early coherence-minimum state. They are historical comparison evidence, not recommended deployment models.

## Which results are actually useful

None of the structural fine-tuning candidates is established as an improved replacement for SOURCE under the combined declared fidelity requirements. Useful A/finite-C gains coexist with native-validation failures; the R5 interpolation export also failed its alternate native check. Keep a small number of those states to inspect that trade-off, not because the run was a successful release.

## Measured redundancy and misleading names

All 806 regular `.pt` files were SHA-256 inventoried. The 384 full model/review checkpoint files were loaded on CPU and inspected for actual saved epoch/update, optimizer presence, selection metadata, model tensors and complete saved state; all loaded successfully. 86 complete-state duplicate groups contain 122 redundant copies, totaling **9.11 GiB** after keeping one representative per group. Complete-state fingerprints recursively include every saved key, tensor dtype/shape/bytes, optimizer, RNG and selection metadata. Matching model weights alone was counted separately and was not treated as proof of interchangeable recovery state. These duplicate savings overlap the 26.52 GiB proposed removal; they must not be added together.

The R5 F, N and S `best.pt`/`best_fidelity.pt` files all represent epoch50, while R5 confirmation’s corresponding files represent epoch0. Those names reflect the fixed-panel selection mechanism and do not establish mature native fidelity. Early SOURCE snapshots, feasible states and exploratory states are not automatically useful merely because they were labeled “best” or “feasible.”

The model files in profile/smoke/sibling directories total 4.53 GiB across 69 files. Their measured timing and execution/recovery contracts remain in logs, ledgers, configs, receipts and PDF/numerical evidence; the compact retention policy does not keep their trained weights. This loses direct replay of those particular saved parameter states, including the optional epoch001 trajectory-difference diagnostic, while retaining its recorded failed result. Keeping one representative bounded sibling state would be a reasonable optional addition if that recovery trajectory is expected to be investigated again.

The R3 retained-review tensor tree contains 23 full checkpoints occupying 1.92 GiB. Some are distinct intermediate models, not byte-identical copies: removing the nonselected review states intentionally gives up replay of those particular intermediate ages. Mature 150/200 states remain in their original campaign paths under this recommendation, and all saved raw metrics/window evidence remains. The same explicit replay trade-off applies to the omitted R2 neighbor/early states; the locked primary130 audit state is retained.

## Exact removal manifest and retained evidence

The [recommended retention manifest](./_cleanup/20261006/checkpoint_review/recommended_retention.json) lists every keep and candidate removal path, current size, SHA-256, saved epoch/update, model fingerprint, full-state fingerprint and rationale. The [checkpoint inventory](./_cleanup/20261006/checkpoint_review/checkpoint_inventory.json) includes duplicate groups and selection metadata. Ten `best_exploratory.pt` symlinks would point to removed targets under this plan; the manifest lists them separately. They must be removed or their original target explicitly retained, never silently retargeted to a different model.

Retain all per-run resolved configs, normalization, family/calibration state, query/panel identities, source/code provenance, metrics and raw denominators, checkpoint identity receipts, stage budgets, logs, contour arrays and PDF masters. Those artifacts are generally smaller and sufficient to preserve recorded findings; saved metrics remain the evidence for mature windows after weight pruning. SOURCE and datasets outside this directory remain outside scope.

Pruning to this list would reduce old arbitrary checkpoint replay and historical full recovery options. Some existing generic commands or historical references to removed `last`/`best`/neighbor paths would no longer resolve; retained files and their hashes should stay at the exact paths listed, and documentation should distinguish intentionally pruned historical paths from runnable retained-checkpoint commands. A future cleanup must recheck hashes, live training/open files, symlinks and the exact manifest immediately before deleting. It must retain a removal receipt and verify all kept files and supporting evidence afterward.
